# kus («Кусь») — подбор рациона для собак

Сервис, который по анкете о собаке считает индивидуальный рацион и отдаёт клиенту
персональный PDF-отчёт. Воронка: **Telegram-бот / лендинг → анкета → оплата (YooKassa)
→ расчёт + персонализация → генерация HTML/PDF → проверка кинологом → доставка
(ссылка в Telegram / ВКонтакте / email)**.
За проектом — реальная кинологическая экспертиза (питомник, диетологи); тон отчётов и
бота на этом строится (см. `messages.py`).

## Позиционирование (ВАЖНО для всех клиентских текстов)

Клиенту **не** говорим «ИИ / нейросеть». Подача: рацион **составлен по ветеринарным
нормам (NRC, FEDIAF, AAFCO) и проверен нашим специалистом** — за результат отвечает
человек. Это правда: `calculator.py` — детерминированная экспертиза (цифры, меню,
покупки, дозировки), Gemini лишь черновик прозы, а каждый отчёт проходит ревью кинолога
перед отправкой. Поэтому:
- В лендинге/боте/статусе/PDF слова «AI/нейросеть» убраны → «персональный разбор»,
  «проверено специалистом». Внутренняя админка (поддержка/«ответ ИИ») — можно как есть.
- В юр. документах (`oferta.html`, `privacy.html`) автоматизацию/Gemini **раскрываем**
  (152-ФЗ), но мягко: «вспомогательные автоматизированные средства» + «проверяет специалист».
- Сроки везде — **до 3 рабочих дней** (это живая работа человека, не мгновенная выдача).

## Два трека

- **natural** — натуральный рацион (BARF / варка). Ядро: `calculator.py` (нормы, Ca:P,
  распределение по группам, подбор продуктов, недельное меню) → `pdf_generator.py`.
- **dry** — подбор сухого корма по составу: `dry_food_selector.py` выдаёт по 3 корма в
  3 ценовых категориях (9 всего) с честным разбором состава.

## Ключевые модули

| Файл | Роль |
|---|---|
| `app.py` | FastAPI-бэкенд: анкета, вебхуки оплаты, генерация и выдача отчёта, админка |
| `bot.py` | Telegram-бот (aiogram): мини-курс, анкета, оплата, доставка. `kus-bot.service` |
| `worker.py` | Фоновая обработка после оплаты: расчёт → AI → HTML → отправка (TG + SMTP) |
| `calculator.py` | Натуралка: весь расчёт рациона и подбор продуктов. `DogProfile`→`DietResult` |
| `pdf_generator.py` | Рендер отчёта (HTML; PDF через weasyprint). Числа сводки/меню/покупок |
| `dry_food_selector.py` | Трек сухого корма: подбор + разбор состава |
| `reconcile.py` | Инварианты согласования сводка↔меню↔покупки (единый источник проверок) |
| `ai_adapter.py` | Gemini (через Vertex): парсинг диагнозов/стоп-продуктов, тексты, меню |
| `declension.py` | Склонение кличек/слов (pymorphy3) |
| `models.py` / `database.py` | Pydantic-схемы анкеты + SQLite (`kus.db`, `bot.db`, `orders.db`) |
| `support_agent.py` | Агент поддержки: 3×/день отвечает клиентам через `claude -p` (подписка, не API) |
| `evals.py` | Эталонные профили + проверки качества (витрина в админке + гейт) |

Данные: `data/breeds.json` (породы, размеры, веса), `data/products.json` (продукты:
группа, бюджет-тир, аллергенность, противопоказания), `data/dry_foods.json` (корма).
Шаблоны: `templates/*.html`. Готовые отчёты: `output/`.

## Запуск

- Прод на **5.42**: `kus.service` = `uvicorn app:app --host 0.0.0.0 --port 8007`,
  `kus-bot.service` = `python3 bot.py`. Деплой — `bash tools/deploy.sh` (гейт → рестарт).
- Локально (dev): `./venv/bin/python app.py` (uvicorn :8000, reload).
- Зависимости: `requirements.txt` (FastAPI, aiogram, weasyprint, pymorphy3, google-genai…).
- Секреты — в `.env` (на 5.42): `BOT_TOKEN`, `ADMIN_TELEGRAM_ID`, `YOOKASSA_*`,
  `GEMINI_API_KEY`/`GOOGLE_*`, `SMTP_*`, `ADMIN_USER/PASS`.

## Самоулучшение: ХРАПОВИК (главное правило)

Модель не обучается — **поднимается «пол» качества и не может опуститься**:

> **Ни один баг согласования не чинится без теста, который бы его поймал.**

Чиня баг (сводка ↔ меню ↔ список покупок):
1. **Корень, не симптом** — правь `calculator.py`/`pdf_generator.py`, не маскируй проверку.
2. **Инвариант** — новый класс бага → проверка в `reconcile.py` (единый источник; дублировать
   в evals/fuzz/snapshot нельзя).
3. **Регресс-профиль** — добавь воспроизводящий профиль в `PROFILES` в `evals.py` с `label`.
4. **Рацион ветеринарно корректен** — частые углы: мелкие собаки 1-3 кг (округление),
   щенки <4 мес (4 кормления), гиганты (заворот → 3 кормления), стоп-листы (выкос группы).

## Ворота (перед коммитом фикса — обязательно)

```

./venv/bin/python tools/snapshot.py --update # одобрить ОЖИДАЕМОЕ изменение рендера
```

## Топология и ночной самоконтроль

## Жизненный цикл заказа и ревью кинолога

Статусы (`models.ORDER_STATUSES`): `new → paid → processing → review → done` (+ `rework`, `error`).
- `processing` — `worker.process_order`: парсинг диагнозов/стопов → расчёт → генерация HTML →
  AI-проза → **авто-проверка (агент)** = `worker._auto_check_natural` (= инварианты `reconcile.py`).
- `review` — отчёт готов, ждёт кинолога. **Клиенту НЕ отправляется автоматически.** Очередь:
  `/admin/review`; карточка: `/admin/review/{id}` (предпросмотр через `/admin/order/{id}/view`,
  правка текстов, решение). Авто-проверка показана кинологу (`orders.auto_check/auto_check_ok`).
- Решения кинолога: **Одобрить** (`approve` → `done` → `worker.deliver_order`),
  **На переделку с замечаниями** (`rework` → `process_order` перегенерит с учётом `review_notes`),
  **Правка текстов** (`edit` → `worker.regenerate_with_edits` перерисовывает БЕЗ новых AI-вызовов,
  тексты берутся из sidecar `output/order_{id}.meta.json`; обложка не перегенерируется).
- AI-тексты редактируемы: натуралка — intro/notes/analysis; сухой — intro/conclusion.
  Правка текстов для комбо-заказов отключена (один sidecar на заказ перетирается dry-частью).

## Отчёты: страницы и доставка

- **Натуралка:** ~10 базовых страниц + 1-3 опц. (персональный анализ) = **10-13 стр.**
  **Сухой корм:** ~**12-13 стр.** (разбор кормов встроен в карточки). PDF ~1-1.5 МБ.
  AI = проза (intro, notes, 6 блоков анализа, обложка-иллюстрация); всё остальное (цифры,
  меню, покупки, добавки, переходная схема) — детерминированный `calculator.py`.
- **Доставка** (`worker.deliver_order`, запускается при одобрении): email (SMTP) и ВКонтакте
  (`VK_TOKEN` сообщества; без токена — пометка для ручной отправки). **Telegram** — циклом
  `bot._delivery_loop` по статусу `done`. Канал клиента: `orders.delivery_channel`
  (`all`/`email`/`telegram`/`vk`), VK-контакт — `orders.vk`. С 5.42 TG недоступен — см. ниже.

## Меню: слоты кормлений

`DayMenu`: `morning` (Утро) · `midday` (День) · `afternoon` (Полдник) · `evening` (Вечер).
- 2: Утро+Вечер. 3 (гиганты/гастрит): вечерний пучок пополам → День+Вечер.
- 4 (щенки <4 мес): оба пучка пополам → Утро+День / Полдник+Вечер.
- Любая новая итерация по слотам ДОЛЖНА включать `afternoon` (иначе недосчёт у щенков).

# Kus reconciliation (из памяти)

Проект kus (рацион для собак) на 5.42 `/opt/kus`, sshfs-маунт `/mnt/5.42-opt/kus`. Запуск эвалов: `./venv/bin/python evals.py` (нужен venv — pdf_generator тянет pymorphy3).

**evals.py теперь сверяет НЕ только объект-расчёт, но и отрендеренный HTML** (рендер без AI, детерминирован). 5 reconciliation-проверок ловят зазор calc↔рендер: слоты=кормления, группы-сводки-есть-в-меню, мясо+рыба=мясной бюджет, яйцо-сводка=покупки, нет-нулей/ложки-уместны. 15 профилей (добавлена матрица углов: гигант 90кг, беременная, кормящая, кроха+2стопа+аллергия), avg ~90%.

**Починен баг единицы яйца** (pdf_generator): сводка-распределение хардкодила `/60` (куриное), а при стоп-курице/аллергии меню переключается на перепелиное (10г) → сводка показывала ~3 шт/нед, а меню/покупки ~17. Теперь вес яйца берётся из реального продукта в `result.weekly_menu`. Демо Граф/Тиша (без стопов) не затронуты.

**РЕШЕНО (commit 8d0cc0b):** если стоп-лист выкашивает ВСЮ группу (субпродукты в БД только говяжьи/куриные → стоп курица+говядина = 0 organs), `_reconcile_wiped_groups` переносит граммы в мясо, обнуляет группу, выводит warning + добавку (вит. A/B12). Меню теперь использует согласованное распределение (`_generate_weekly_menu(..., distribution)`), а не пересчитывает независимо — заодно убран дрейф сезон/беременность. Все 15 профилей зелёные по reconciliation (avg ~91%).

Сервисы на 5.42: `kus.service` (uvicorn app:app, порт 8007 — рендерит отчёты через worker.process_order; рестартить ПОСЛЕ правок calculator/pdf_generator) и `kus-bot.service` (bot.py — не импортирует calc, рестарт не нужен). Прогон evals через sshfs-маунт долгий (~90с — латентность ФС, не код; на 5.42 локально быстро). Связано: [[server-project-map]].
